# Quality check 2026-11-01

The ten quality rules checked against the code, with evidence. Python 3.14.5, torch 2.14.1+cpu,
Windows 11, Intel Core i7-13700H. The GPU run (`make run`) was not repeated: no change touches the
measured code paths, so the recorded numbers stand.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Every call can fail | fixed | The only network call is `sources.fetch` (`urlopen(..., timeout=60)`, HTTPS only, one attempt; a failed run is re-run by hand). Found: the body was copied with no size limit, so a wrong or hostile server could fill the disk before the hash check, and an interrupted download left a `.part` file. Now `copy_limited` refuses more than the pinned size and the partial file is deleted on any error (`test_copy_limited_refuses_a_longer_body`, `test_failed_download_leaves_no_partial_file`). The two `except Exception` blocks in `nvml_energy`/`nvml_sm_clock` are a documented fallback: without a driver the reading is `None` and is recorded as `null` in the results, not hidden. `ruff` with `S`, `B`, `PIE` rules: clean. |
| 2 | Writes safe to retry | fixed | Downloads go to `.part` and are renamed only when complete, then hash-checked. Found: `eio run` wrote the results JSON in place, so a crash could leave half a file; now `write_atomic` writes a temporary file and renames it (`test_write_atomic_replaces_whole_file`). Re-running a command rewrites the same files. |
| 3 | No race conditions | N/A | Single process, single thread; no shared state across threads or awaits. |
| 4 | Don't trust the clock | pass | Latency, throughput and the GPU warm-up use `time.perf_counter` (`bench.py` `latency_ms`, `throughput`, `gpu_warmup`). No timestamps are stored. |
| 5 | Read before changing | pass | APIs checked against the installed versions (mypy --strict clean against torch 2.14.1 and transformers 5.22.1). The code reads no environment variables; it only sets cache variables (`env.CACHE_VARS`, documented in the module). Makefile variables (`TORCH_INDEX`, `TORCH_GPU_INDEX`, `TORCH_VERSION`) are commented in the Makefile. Paths in the README exist. |
| 6 | Never break compatibility | pass | The results JSON format is unchanged; `eio show` now checks the fields it prints and refuses a file without them instead of failing with a `KeyError`. |
| 7 | One source of truth | pass | Model and data are pinned once in `sources.py` (revision, size, SHA-256); the run deletes them afterwards and `make run` downloads them again. torch version: Makefile `TORCH_VERSION ?= 2.14.1`, README "PyTorch 2.14": consistent. |
| 8 | Small changes, no secrets, validate input | fixed | Secret scan (`git grep -niE "password|secret|api[_-]?key|token"`): only tokenizer names. Inputs: `--limit` must be positive, `--variants` is a fixed choice, the held-out file is schema-checked (`data.load_parquet`), the output path must stay in the repository (`env.ensure_inside`). Found: `eio show` on a missing or malformed file ended with a traceback; now a clear error and exit 2 (`test_show_refuses_bad_results_files`). No new dependency (`shutil` dropped). |
| 9 | Tests that can fail | fixed | No tautologies or skips (`git grep -n "skip\|xfail"` in tests: none). Mutation table below: 13 of 17 killed before; after, 16 of 16 non-equivalent mutants killed. |
| 10 | Re-verify | pass | `ruff check .`: All checks passed. `ruff format --check .`: clean. `mypy`: no issues in 11 source files. `pytest -q`: 22 passed (16 before). `pip-audit --skip-editable`: No known vulnerabilities found; `torch==2.14.1` audited on its own: No known vulnerabilities found. ## Known limitations

- `write_atomic` cannot be checked for crash safety in a unit test; it relies on `Path.replace`
  being an atomic rename on one file system.
- The download makes one attempt; a network failure stops `eio prepare`, which can be re-run.
